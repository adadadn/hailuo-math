# 考研数学 Viberecoding M1 自适应每日一练 MVP spec v0.3

> 文档状态：待产品确认，确认后才进入研发。  
> 版本：M1 / v0.3  
> 编写日期：2026-09-22

## 1. 背景与目标

### 1.1 背景

考研数学用户需要在数学一、数学二、数学三、396 等项目之间管理章节、真题和模拟题，并能根据真实练习记录安排每天的练习。普通题库只能提供静态练习，无法将作答、错题、打卡和下一次题目选择连接起来。

### 1.2 M1 目标

在一个手机优先、可部署访问的 Web 学习工作台中，完成以下可验证闭环：

```text
选项目/章节 → 设置当天题量 → 自适应组卷 → 作答和对答案
→ 保存学习结果/错题 → 自动打卡 → 影响下一次题单
```

### 1.3 目标用户

备考数学一、数学二、数学三、396 的个人考生。M1 优先服务单一用户的个人学习数据，不处理多人协作。

## 2. 需求描述（PRD 部分）

### 2.1 功能清单

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| F1 | 考试项目选择 | 支持数学一、数学二、数学三、396；项目决定可见章节和题目集合。 |
| F2 | 章节浏览 | 用户查看项目下的一级章节与二级知识点，进入对应题目练习。 |
| F3 | 题库管理 | 维护真题和章节模拟题的题干、答案、解析、来源、项目、章节、知识点、难度。 |
| F4 | 每日题量设置 | 用户设置当天希望完成的题量；系统保存该偏好。 |
| F5 | 自适应每日组卷 | 从已审核题库中按项目、章节范围和历史结果选择题目，生成当天题单。 |
| F6 | 作答与对答案 | 用户提交客观答案或学习结果；系统展示标准答案和解析。 |
| F7 | 学习记录与错题 | 保存每题结果、耗时、错误原因和最终确认状态；错误题进入错题集合。 |
| F8 | 自动打卡 | 当当天题单全部完成时创建打卡记录。 |
| F9 | 移动端与 PWA | 响应式适配手机屏幕，提供可安装到主屏幕的基础 PWA 能力。 |

### 2.2 用户旅程

1. 用户首次进入，选择一个考试项目。
2. 用户查看可练习章节，并设置今日题量，例如 5 题或 10 题。
3. 用户点击“开始今日一练”；系统创建当天固定题单。
4. 用户逐题在线作答并提交答案或学习结果。
5. 用户提交后查看答案、解析和系统判断；必要时修改最终学习结果。
6. 用户完成题单，系统创建当天打卡，并更新错题、章节统计和下一次组卷依据。

### 2.3 关键业务规则

1. 一份每日题单一经生成，当天不因再次进入而静默变化。
2. “自动生成”指从已有、已审核题库中自适应组卷，不指 AI 临时出新题。
3. 每道入选题必须存在标准答案、解析、考试项目和至少一个章节/知识点标签。
4. 用户当天可调整题量，但调整后只能显式重新生成未开始的题单；已开始的题单不自动替换。
5. 每题最终结果为：`correct`、`incorrect`、`unknown`、`partial`、`pending_confirmation` 之一。
6. 客观题可以自动核对答案；非客观题由用户确认学习结果。
7. 错题至少包括 `incorrect` 和 `unknown`；`partial` 是否计入错题由产品配置决定，M1 默认计入。
8. 当题单内每道题都具有最终确认结果时，系统自动创建或更新当天打卡记录。
9. 同一用户、同一天、同一考试项目只保留一条有效打卡记录。

## 3. 实现方案（spec 部分）

### 3.1 技术与部署边界

M1 建议采用手机优先的响应式 Web 应用：在 Codex 工作区内开发和运行，并部署到 HTTPS 地址供手机浏览器访问。浏览器作为用户操作界面；应用服务负责业务逻辑，学习数据存放在可备份的数据目录或数据库中。

产品包含 Web App Manifest、应用图标和安装引导，以支持用户添加到手机主屏幕。离线练习、后台同步和推送通知不作为 M1 必须能力。具体框架、数据库和正式托管方式在启动研发前确认；M1 不包含豆包能力或微信小程序发布。

### 3.2 系统模块

```text
Web UI
├── 项目与章节页
├── 每日一练页
├── 作答/解析页
└── 打卡与学习记录页

应用服务
├── 项目/章节服务
├── 题库服务
├── 每日组卷服务
├── 作答与学习记录服务
└── 打卡服务

数据层
├── 考试项目与章节
├── 题目、答案、解析、标签
├── 每日题单与题单明细
├── 作答、错题、掌握状态
└── 打卡记录
```

### 3.3 数据模型（逻辑层）

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| ExamProject | id, name, code, status | 数学一、数学二、数学三、396 等。 |
| Chapter | id, project_id, parent_id, name, sort_order | 支持章节和知识点层级。 |
| Question | id, type, stem, answer, explanation, source, difficulty, review_status | 题目主体；仅 `approved` 题目可进入正式组卷。 |
| QuestionScope | question_id, project_id, chapter_id | 建立题目与项目、章节的多对多关系。 |
| DailyPractice | id, practice_date, project_id, requested_count, status | 一次当天固定题单。 |
| DailyPracticeItem | practice_id, question_id, sort_order, selection_reason | 题单内题目及被选择原因。 |
| Attempt | id, practice_item_id, submitted_answer, result, duration_seconds, confirmed_by_user | 单题作答与最终结果。 |
| MistakeRecord | id, attempt_id, reason_code, note, review_status | 错题与个人复盘。 |
| CheckIn | id, check_in_date, project_id, practice_id, completed_at | 自动打卡记录。 |

### 3.4 每日组卷规则（M1）

输入：考试项目、用户选择的章节范围、当天题量、历史作答记录。

候选题过滤：

1. 题目属于选定考试项目和章节范围。
2. 题目状态为已审核。
3. 题目有答案和解析。
4. 排除当天已完成或近期重复的题目；近期窗口初始建议为 14 天，作为可配置参数。

排序因素：

1. 错题和低掌握度知识点优先。
2. 长时间未复习的知识点优先。
3. 保留一定比例的正常巩固题，避免题单只由难题组成。
4. 按真题/模拟题的配置比例取题；默认比例在研发前确定。
5. 题目数量不足时，明确提示用户并允许放宽章节或重复窗口。

输出：固定题单、每题选择原因、生成时间和使用的规则版本。

### 3.5 作答与对答案

- 选择题、填空题：M1 支持文本/数值答案的自动比对；答案格式需要在题目数据中明确。
- 解答题：M1 展示标准答案和解析，用户选择正确、错误、不会或部分正确。
- 用户确认动作写入最终结果，并作为错题和后续组卷的唯一统计依据。

### 3.6 文件与版本管理

- 原始题目资料与结构化学习数据分离保存。
- 代码仓库配置 `.gitignore`，忽略本地数据库、运行产物和未来外部服务所需的私密配置。
- 开发开始前初始化 Git，并在 M1 验收通过时提交可回退版本。

## 4. 验收标准

1. 在初始化数据中，四类考试项目均可选择，且每类至少能展示章节结构。
2. 用户设置题量后可以创建每日题单；题单题数等于设置值，或在题库不足时显示明确原因。
3. 每题均能查看答案、解析、来源和所属章节。
4. 用户完成一道题后，其最终结果、耗时和错题状态可被保存；重新进入后数据仍存在。
5. 完成题单全部题目后自动生成当天打卡；刷新页面后打卡仍存在，不会重复创建。
6. 再次生成符合条件的练习时，系统可展示至少一个与历史表现相关的选题原因。
7. 在常见手机尺寸下，用户无需横向滚动即可阅读题目、完成作答、查看解析和完成打卡。
8. 在支持安装的手机浏览器中，用户可将应用添加到主屏幕并从该入口打开；不支持时仍能在浏览器正常使用。

## 5. 边界与后续

### 5.1 M1 明确不做

- AI 自动生成新题并无审核地进入题库。
- 主观题步骤的自动打分或保证数学结论正确。
- 图片上传、拍照识别和豆包模型/API 调用。
- 用户账号、多人协作、跨设备同步。
- 完整学习计划排程、课程体系、商业化能力。
- 在豆包 App 内直接运行产品或微信小程序发布。
- 原生 iOS/Android 应用商店包。

### 5.2 M2 规划方向

- 相机/相册上传作答照片。
- 豆包模型/API 调用、结果展示和用户确认。
- 图片分析失败或低置信度时的手动回退。
- 当天题单的关键页面缓存。

## 6. 待确认项

1. 每日默认题量，以及可允许的最小值和最大值。
2. 真题和模拟题的默认组卷比例。
3. 用户是否只可从已学习章节组卷，是否允许预习章节。
4. 第一批题库由谁提供、格式为何、是否拥有使用授权。
5. MVP 首批支持的题型及每类题目的答案格式。
6. M1 测试环境使用的 HTTPS 部署地址与数据备份方案。
